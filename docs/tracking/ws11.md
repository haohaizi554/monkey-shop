WS11 turns MonkeyShop telemetry into a data-bank style tracking and profile system. It records browser and backend events, updates user and product profiles, exposes a real-time dashboard, and keeps funnel conversion metrics visible in Prometheus and Grafana.

## Goals

- Track page views, clicks, searches, product views, cart additions, order creation, and payment success with trace ids.
- Build user profile tags from behavior and interest signals while storing sensitive summaries with Tink encryption and HMAC blind indexes.
- Build product profiles from category, behavior, sales, and review signals.
- Expose a management dashboard with PV, UV, order count, payment amount, and search-to-payment funnel conversion.
- Reuse `VisitMetricsService`, `BusinessMetricsService`, `AuditService`, OpenTelemetry spans, Snowflake ids, API rate limiting, and Grafana dashboard packaging.

## Acceptance

- `tracking_event` stores all client and backend events with Snowflake ids, trace id, session id, indexes, and foreign keys.
- `user_profile_tag` encrypts profile summaries and stores blind indexes; behavior and interest tags remain queryable JSON.
- `product_profile` aggregates product tags, sales count, and review score.
- `/api/tracking/events` is rate limited and may accept anonymous page events; dashboard/profile reads require tracking permissions.
- The tracking SDK in `TrackingSdk.ts` records route page views and click events from the Vue shell.
- `DashboardView.vue` refreshes every five seconds and displays funnel conversion.
- `grafana-dashboard.yaml` contains tracking event and funnel panels.
- `scripts/verify-ws11-data.ps1` and `Ws11DataWorkflowTest` prove the artifacts stay wired together.

## Invariants

- Domain types stay framework-free records, enums, and interfaces.
- All writes are `@Transactional`; dashboard/profile reads are `@Transactional(readOnly = true)`.
- All event ids come from the shared `IdGenerator`.
- Profile summaries are encrypted through `PiiCryptoService` and indexed with HMAC.
- Key operations write audit events and are traced with `@WithSpan`.
