# WS7 Logistics Tracking

## Goal

WS7 turns order fulfillment into a logistics center instead of a text tracking number field. It adds carrier adapters for SF, ZTO, and YTO, a tracking state machine, freight templates, address parsing, signed webhook replay protection, PII protection for recipient data, and a Vue logistics console.

## Invariants

- Tracking ids and tracking numbers are generated by the shared Snowflake `IdGenerator`.
- Tracking changes only move through the logistics state machine: `ORDERED -> PICKED_UP -> IN_TRANSIT -> OUT_FOR_DELIVERY -> SIGNED`.
- Webhook delivery is authenticated with an HMAC-SHA256 signature and idempotent through Redis `SETNX` with database uniqueness fallback.
- Recipient phone and address snapshots are encrypted through `PiiCryptoService` and searchable only by HMAC blind index.
- Freight is calculated across weight, item count, and region templates, with the highest applicable regional surcharge included.
- Address parsing normalizes province, city, district, and detail text and applies deterministic typo correction.
- All carrier calls are replaceable adapters guarded by `@ConditionalOnProperty`.
- All user-facing reads are rate-limited by the API rate limiter and protected by ownership checks.
- Important operations write audit events and expose OpenTelemetry spans.

## Acceptance

- Freight quote combines weight ladder, item ladder, and region surcharge.
- Address text is parsed into province, city, district, and detail fields with typo correction.
- Illegal tracking state transitions are rejected before persistence.
- Invalid webhook signatures are rejected before state changes; replayed webhook events return the existing tracking state and create no duplicate tracking event.
- Logistics routes are available from the SPA through `LogisticsView.vue` and `frontend/src/api/logistics.ts`.
- `scripts/verify-ws7-logistics.ps1` and `Ws7LogisticsWorkflowTest` prove the WS7 artifacts stay wired together.
