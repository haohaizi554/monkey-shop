# WS12 Multi-Tenant SaaS Isolation

## Goal

Turn MonkeyShop into a tenant-aware SaaS platform comparable to Youzan and Shopify operations: every merchant has an isolated `tenant_id`, platform operators can manage lifecycle and configuration, and billing/export workflows are auditable.

## Scope

- Tenant isolation: `tenant_id` is added to user, order, catalog, inventory, marketing, cart, payment, logistics, membership, search, risk, tracking, audit and idempotency data.
- Tenant context: JWT carries `tenant_id`, `TenantContextFilter` injects it into `TenantContext`, and `TenantScopedEntityListener` fills tenant scoped JPA entities.
- Tenant lifecycle: onboarding, renewal, expiry downgrade and platform visibility are handled by `TenantApplicationService`.
- Tenant configuration: payment, logistics, marketing and rollout settings are stored per tenant with immutable config history.
- Tenant billing: monthly plan fees plus order-count tiers are generated with order/payment reconciliation inputs.
- Tenant data export: GDPR/PIPL export jobs are queued, audited and completed by a ShedLock scheduler with encrypted archive paths.
- Tenant rollout: `tenant_rollout_policy` and `ROLLOUT` configs model per-tenant Argo Rollouts canary targeting.

## Invariants

- Domain classes under `com.example.monkey.tenant.domain` stay framework-free.
- All write use cases are `@Transactional`; all reads are `@Transactional(readOnly = true)`.
- Tenant PII, including contact phone, is encrypted through `PiiCryptoService` and indexed by HMAC.
- Tenant IDs are generated by the shared Snowflake `IdGenerator`.
- Tenant admin APIs are protected by `TENANT_READ` and `TENANT_ADMIN`.
- Tenant-facing APIs pass through `ApiRateLimitOperation.TENANT` and the authenticated limit key includes tenant ID.
- Export completion uses `@SchedulerLock(name = "tenant-data-export")`.

## Acceptance

- Cross-tenant data has an explicit `tenant_id` column and tenant indexes/FKs on critical tables.
- JWT parsing preserves tenant ID in `SessionUser`.
- Tenant context is available to web requests and JPA tenant-scoped writes.
- Tenant config history, bills and data exports are persisted through replaceable JPA adapters.
- `TenantAdminView.vue` exposes the current tenant operations surface.
- `scripts/verify-ws12-saas.ps1` and `Ws12SaaSWorkflowTest` prove the artifacts are wired end to end.
