# WS10 Risk Control and Anti-Fraud

WS10 adds a risk control slice for multi-account abuse, seckill scalpers, self-buy order fraud,
price anomalies, score-based blocking, and manual review. The implementation reuses the existing
PII blind-index service, Redis-backed runtime state, TOTP verifier, user-level JWT revocation,
audit log, Micrometer metrics, and PrometheusRule alerts.

## Scope

- Device fingerprint, client IP, and phone HMAC are combined to detect multi-account behavior.
- Seckill attempts are grouped by activity, product, and device fingerprint so same-product
  multi-account bursts can be blocked in real time.
- Seller self-buy signals move the order to manual review.
- Product price movements above 50 percent create a price anomaly signal and automatically unlist
  the SPU.
- Risk scores are calculated from 0 to 100. Scores at or above 80 require TOTP or rate limiting;
  block-level decisions revoke user tokens through `SessionTokenService.revokeUserTokens`.
- Non-allow decisions create `risk_audit_queue` records for the administrator workbench.

## Invariants

- The domain layer has no Spring, JPA, Hibernate, or Redis dependency.
- Phone matching uses `PiiCryptoService.blindIndexPhone` or the same blind-index path used by PII
  fields.
- Runtime device fingerprint state is cached under Redis keys with a 30-day default TTL.
- Risk scores are cached under Redis keys with a 30-minute default TTL.
- Blocking decisions always write audit events and revoke user-level JWT families.
- Price anomaly decisions never silently leave a listed product online.
- Manual `BLOCKED` review decisions require administrator TOTP.

## Acceptance

- Multi-account wool-party detection scores the same device with distinct phone HMACs.
- Seckill scalper detection blocks same-product multi-account attempts.
- Price jumps above 50 percent auto-unlist the product and emit a Prometheus-visible metric.
- Risk score 80 and above is moved to TOTP/rate-limit handling and manual review.
- The review workbench can list and resolve pending risk cases.
