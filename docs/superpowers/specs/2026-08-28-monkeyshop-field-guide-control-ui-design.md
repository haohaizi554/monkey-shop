# MonkeyShop 全站视觉重构设计规格

日期：2026-08-28

状态：用户已授权自主决策；已自审；直接进入实施

方案：自然图鉴式消费商城 + 安全认证检查站 + 商业运营控制台

本规格取代 `2026-07-12-monkeyshop-ui-experience-design.md` 与
`2026-07-13-monkeyshop-kawaii-commerce-system-design.md` 中冲突的视觉方向、密度、版式和品牌使用规则。
旧规格中已经落地并由测试保护的路由所有权、权限、异步状态、错误恢复、响应式、键盘操作、
无障碍和业务接口契约继续有效。

## 1. 目标

1. 重做全部 25 个前端视图的视觉层次、版式、组件表面、状态细节、深色主题和响应式表现。
2. 消费端以真实商品图片和自然图鉴式信息组织建立可信、独特、具有购买节奏的品牌体验。
3. 认证端保持欢迎感，但验证码、MFA、密码策略、限流和错误状态必须严肃、清晰、可恢复。
4. 后台端形成稳定、紧凑、可扫描的运营控制台，不把消费端的装饰性语言塞进数据工作区。
5. 保留现有功能、API、路由、权限和自动化选择器；视觉重构不制造业务回归。
6. 通过静态检查、单元测试、构建、全路由浏览器检查、Axe、视觉快照、深色模式和目标视口证据证明完成。

## 2. 非目标与边界

- 不修改后端接口、业务规则、权限模型、支付或履约流程。
- 不新增虚构商品、指标、评价、品牌合作方或营销承诺。
- 不替换 Vue、Element Plus、Pinia、Vue Router 或现有测试基础设施。
- 不通过全局缩放、强制横屏或缩小字号伪装响应式完成。
- 不为追求效果加入渐变背景、玻璃拟态、霓虹、超大圆角、表情符号图标或无意义循环动画。
- 不把吉祥物放进每张卡片、每行表格或安全决策界面；它只承担品牌引导与状态说明。

## 3. 产品视觉架构

### 3.1 共享品牌层

三类区域共享：

- MonkeyShop 名称、现有圆形猴子品牌头像和现有 12 组状态吉祥物资产。
- 语义色、状态色、焦点环、间距、控件尺寸、图标尺寸、动效时长和层级体系。
- `PageHeader`、`AsyncStateView`、`InlineNotice`、`StatusTag`、`DataTableShell`、
  `FormSection`、`ConfirmAction` 的行为与无障碍契约。
- 价格、库存、订单号、SKU、时间、风险分和指标使用等宽数字。

### 3.2 消费端：Canopy Field Guide

消费端采用自然史图鉴与现代编辑型电商的结合：

- 真实商品图是第一视觉，吉祥物退到页面引导、空态、成功态和帮助状态。
- 页面使用温暖纸张色画布、深林墨色文字、叶绿主动作、金褐价格强调和珊瑚风险提醒。
- 商品名称、价格、品种、毛色、库存和仓储信息形成稳定的“标本索引线”。
- 页面不堆叠通用白卡；重复实体才用卡片，章节通过留白、细线和背景带分组。
- 导航突出发现、搜索、购物车和订单；次要入口降低权重，移动端保持底部主任务导航。

### 3.3 认证端：Secure Checkpoint

- 保留一幅欢迎吉祥物作为品牌锚点，表单本身使用克制、窄而清晰的安全工作区。
- 登录、注册、重置模式具有明确选中状态；字段、验证、错误和提交动作维持单向阅读顺序。
- 限流、MFA、验证码、密码规则和强制改密使用内联状态，不使用庆祝性动效或卡通化警告。
- 移动端首屏优先表单与核心品牌，不出现无意义大图空白。

### 3.4 后台端：Commerce Control Observatory

- 深林色侧栏与纸白内容画布形成稳定工作区；激活项使用金褐信号，不使用发光或渐变。
- 顶栏负责面包屑、命令搜索和账户动作；页面标题、工具栏、指标和表格各自只承担一层信息。
- 数据表、筛选器、状态标签、时间线、抽屉和确认对话框优先可扫描性与操作反馈。
- 空态、帮助和风险提示可使用对应吉祥物，但正常数据密集页面不使用装饰插画。

## 4. 设计令牌合同

### 4.1 浅色主题

- `--color-canvas: #F3F1EA`
- `--color-surface: #FFFCF6`
- `--color-surface-subtle: #EAEDE7`
- `--color-surface-raised: #FFFFFF`
- `--color-ink: #17312A`
- `--color-muted: #66736E`
- `--color-line: #D7D9D2`
- `--color-line-strong: #AAB3AC`
- `--color-primary: #126B5B`
- `--color-primary-strong: #0B4F43`
- `--color-primary-soft: #DCEDE7`
- `--color-accent: #A8691F`
- `--color-accent-soft: #F6E7C9`
- `--color-info: #315F9C`
- `--color-danger: #B4493D`

后台 chrome 使用 `#10231D`、`#1A3028`、`#F4F7F3`、`#AFC0B7` 与 `#D8A54A`。
状态色保持互相独立，不把品牌主色复用为所有成功、信息和警告状态。

### 4.2 深色主题

深色主题使用低饱和石墨绿而非纯黑：画布 `#0E1512`，表面 `#16201C`，
抬升表面 `#1E2A25`，正文 `#EFF5F1`，弱文字 `#A8B5AE`，边线 `#35453D`。
主色提升到 `#78CBB3`，金褐提升到 `#E2B56A`。所有 Element Plus 变量必须从语义令牌桥接。

### 4.3 字体与排版

- 继续使用已本地打包的 `Noto Sans SC Variable`，不依赖运行时字体 CDN。
- 消费端一级标题为 40–52px 流体字号、750–800 字重；页面正文 16–18px。
- 后台一级标题为 24–30px；表格和工具栏正文 14px；关键指标 24–32px。
- 正文行高 1.55，说明文 1.7；标题不使用负字距。
- 使用 `text-wrap: pretty`、合理行长和 tabular numerals；禁止通过缩小到 12px 以下解决空间问题。

### 4.4 空间、形状与层级

- 保留 4px 基线，增加语义容器间距：紧凑 12、常规 20、章节 32、页面 48–72px。
- 控件圆角 8px，重复实体和主要表面 12px，弹层 16px；胶囊只用于状态与筛选标签。
- 阴影仅用于浮层、粘性导航和可交互重复实体；普通章节依靠边线和背景层次。
- 最小触控目标 44px；桌面图标按钮至少 36px。
- 动效为 140ms 反馈与 220ms 结构变化；`prefers-reduced-motion` 下禁用非必要位移和缩放。

## 5. 壳层与导航

### 5.1 消费端

- 桌面头部最大宽度与主内容对齐，品牌、核心导航、工具动作形成三段式布局。
- 核心导航突出“发现、搜索、购物车、订单”；分类、推荐和会员作为次级但仍可达入口。
- 当前项同时通过文字权重、底部短线和柔和底色表达，不只依赖颜色。
- 移动头部只保留品牌、搜索、购物车、语言；底部导航保留五个主任务并适配安全区域。

### 5.2 后台

- 桌面侧栏宽 248px，导航组标题弱化，当前项使用金色信号线与深浅表面对比。
- 顶栏高度 64px，命令搜索居中，账户和主题动作在右侧形成稳定按钮组。
- 900px 以下变为抽屉；焦点捕获、Escape、遮罩和焦点返回沿用现有行为契约。

### 5.3 内容轨道

- 消费端内容最大宽度 1320px；详情页允许 1440px 以容纳图片与购买面板。
- 后台内容使用可伸缩工作区，不给宽表设置页面级最大宽度。
- 页面级横向滚动始终禁止；宽表和多维工具栏使用明确的局部滚动所有者。

## 6. 共享组件视觉规则

- `PageHeader`：消费端可以包含小型品牌视觉；后台仅保留眉题、标题、说明和右侧动作。
- `ProductCard`：图片占主导，正文提供名称、品种、描述、价格和库存；整卡可发现但按钮操作互不冲突。
- `AsyncStateView`：loading、updating、empty、error、success 互斥；更新时保留旧数据。
- `StatusTag`：统一高度、字重和图标规则；危险/警告/信息/成功不得只靠颜色区分。
- `DataTableShell`：工具栏、局部滚动、表头、行悬停、选中、空态和分页形成完整表面。
- `FormSection`：标题、说明、字段网格、内联错误和提交区对齐；长表单通过章节节奏而非嵌套卡片组织。
- `InlineNotice`：低干扰背景、明确图标、标题和恢复动作；原始后端消息永不直接显示。
- 对话框、抽屉、下拉和弹出层必须具有 hover、focus、active、disabled、loading 和错误状态。

## 7. 页面覆盖

### 7.1 消费者与认证

以下页面全部迁移，不允许只修改首页：

- `LoginView`
- `ShopView`、`SearchView`、`RecommendView`、`ProductDetailView`
- `CartView`、`CheckoutView`、`PaymentView`
- `OrdersView`、`ReviewView`、`LogisticsView`
- `MembershipView`、`ProfileView`
- `NotFoundView`

### 7.2 后台

- `AdminView`、`InventoryView`、`MarketingView`
- `DashboardView`、`RiskReviewView`、`TenantAdminView`
- `OrderOperationsView`、`ReturnOperationsView`、`PaymentOperationsView`
- `LogisticsOperationsView`、`MemberOperationsView`

每个页面至少核对：首屏层级、主动作、表单/表格密度、空态、错误态、loading/updating、
窄屏、深色、键盘焦点、文字换行和无页面级横向溢出。

## 8. 响应式策略

- 验收宽度：320、375、390、768、1024、1440 和 1920px。
- 消费端商品网格按可用空间从 1 列到 4 列，使用 `minmax()` 和容器查询，不硬编码每个页面一套断点。
- 商品详情、结算摘要、账户页面在窄屏切换为单列；主动作可粘性但不得遮挡内容或底部导航。
- 后台移动端保留应急查看和单项操作；真正二维表格保留局部滚动，不缩放成不可读微型表格。
- 统一壳层断点为 760px 与 900px；组件优先使用 480、640、900、1200px 或容器查询，逐步移除零散私有断点。

## 9. 可访问性、性能与稳定性

- 每页只有一个 `main` 和一个当前页面 `h1`；路由切换后焦点落到标题或主内容。
- 键盘可完成导航、筛选、表单、标签页、弹层、抽屉和确认流程。
- 深浅主题文本、控件、状态和焦点环满足 WCAG AA；Axe 不允许 serious/critical 问题。
- 图片保留固有比例、可靠回退、明确 alt 和懒加载；首屏关键图按现有策略预加载。
- 路由继续懒加载；不引入大型动画库、运行时字体 CDN 或无必要 UI 框架。
- 视觉修改不得破坏现有请求竞态、幂等、权限、状态恢复和错误映射测试。

## 10. 验收定义

完成必须同时具备以下当前证据：

1. 25 个页面和共享壳/组件均消费新的设计合同，不存在显著旧主题孤岛。
2. 消费、认证、后台三种区域视觉职责清晰，但品牌、状态和交互反馈一致。
3. `npm run typecheck`、`npm run lint`、`npm run format`、`npm run test:unit`、
   `npm run test:api-contract` 与 `npm run build` 全部通过。
4. `npm run test:ui-smoke`、`npm run test:a11y` 和 `npm run test:visual` 全部通过；
   视觉基线仅在逐张人工检查后更新。
5. 320–1920px 无页面级横向溢出，宽表只在局部滚动容器内滚动。
6. 代表性消费、认证、后台页面在浅色、深色、桌面和移动端均有当前截图证据。
7. 控制台无应用错误和警告，没有意外失败请求、卡死 loading、遮挡主动作或不可恢复状态。
8. 最终源码扫描不新增游离颜色、私有圆角/阴影/动效体系、原始后端文案或无意义装饰。

## 11. 自审结果

- 范围覆盖消费者、认证和后台全部现有视图，没有把“全量”缩减为首页换肤。
- 规格只调整前端视觉与布局，不越界修改业务接口或后端规则。
- 颜色、字体、密度、壳层、组件、状态、响应式和验收均有明确决策，无待定项。
- 与旧规格冲突时以本规格为准；已通过测试的行为契约继续有效。
