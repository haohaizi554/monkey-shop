# Stage 9C 接口覆盖审查

日期：2026-07-19

## 结论

- 共识别 124 个规范化 HTTP 端点：用户界面 66 个、管理界面 43 个、机器回调 2 个、API-only 13 个。
- 前端 17 个 API 模块共导出 107 个界面客户端，均能追溯到非 API 层的页面或工作流使用点。
- 13 个 `@Scheduled` 作业没有暴露为浏览器接口，定时任务与 HTTP 接口边界保持分离。
- 本阶段已补齐订单、退款、支付、物流、会员五组后台操作界面，并收紧浏览器可调用的服务端边界。

完整逐端点证据见
[2026-07-19-stage-9c-endpoint-surface-inventory.md](./2026-07-19-stage-9c-endpoint-surface-inventory.md)。

## 审查方法

1. 通过 Spring 合并注解反射扫描所有 `@RestController`，按 HTTP 方法、规范路径、处理器和授权表达式生成清单。
2. 将 Spring Security 过滤器拥有的 `/api/v1/users/logout` 作为显式边界纳入清单，避免控制器扫描漏报。
3. 动态扫描 17 个 `frontend/src/api` 模块，并检查每个公开客户端是否存在页面或工作流消费点。
4. 用独立契约测试禁止浏览器导出机器回调、库存编排、旧物流发货和旧会员自指向管理接口。
5. 对新增后台路由执行组件交互、路由元数据和 Axe 可访问性验证。

## 已修复问题

- **注销端点漏报**：原控制器清单无法看到由 `SecurityFilterChain` 处理的注销接口，现已加入合成边界并纳入唯一性、鉴权和覆盖测试。
- **机器边界泄漏到浏览器**：移除物流 webhook 和旧发货客户端，支付回调继续保持服务端专用。
- **库存编排边界不清**：移除浏览器直接扣减和补偿库存的客户端，保留订单编排服务调用。
- **会员管理目标不明确**：移除旧的浏览器自指向积分和等级客户端，新增显式 `userId` 的管理员积分、等级和降价扫描工作区。
- **无界用户追踪查询**：移除任意用户画像浏览器客户端，保留受控集成 API。
- **契约脚本失真**：原静态抽样检查已改为全模块动态扫描，并强制所有公开客户端存在真实界面消费点。

## 保留的非界面接口

- `MACHINE_ONLY`：支付回调、物流 webhook，共 2 个。
- `API_ONLY`：目录写入 2 个、库存编排 2 个、旧物流兼容 1 个、旧会员兼容 2 个、追踪集成 2 个、上传集成 4 个，共 13 个。
- `SCHEDULED_INTERNAL`：13 个定时作业，均不属于 HTTP 控制器，因此端点清单计数为 0。

## 剩余验证

- Stage 10 在本地完整服务启动后，对运行态 OpenAPI、状态码、响应头、CSRF、限流和真实权限矩阵做一次端到端比对。
- API-only 的旧物流和旧会员兼容端点目前有明确分类与测试，但后续版本应在确认无外部调用方后安排废弃。
